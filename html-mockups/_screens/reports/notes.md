# Accident reports — change notes

Route: `/admin/reports`
Mockup: `html-mockups/_screens/reports/index.html`
Editable CSS: `html-mockups/_screens/reports/screen.css`

## What changed
- Restyled the screen to match the landing page and the redesigned dashboard: ink-black ground, cream text, signal orange and hazard amber accents, Jost headings, orange letter-spaced eyebrow, and the thin caution-tape strip under the header. The sidebar is identical to the dashboard's (orange line icons, orange-bar active item, amber count pill).
- Page header: eyebrow, large title, one-line subtitle, and the two export buttons (CSV, Print / PDF) moved up to the right of the title as outlined orange buttons.
- Filter bar is now one raised panel with two rows: search (with a search icon) + status + type, then municipality + from/to dates + the Flagged and Verified-only toggles + Filter and Clear. The toggles are pills that light up orange when checked. Inputs are dark with an orange focus ring.
- Reports table: transparent rows on a raised panel with an orange top edge, small-caps column headers, orange report IDs, orange hover tint, date column kept on one line, and a wider Location column so addresses wrap to two lines instead of four. Status badges keep their shared colours but are single-line pills (only "Additional Information Required" may wrap).
- The `flagged` marker is now a small red pill with a glowing dot.
- Pager buttons are outlined and go orange on hover; disabled buttons are dimmed.
- Under 768px each row becomes a card: ID + status on the first line, place on the second, then date · type · officer. Under 576px the filter controls sit two per row.

- Added a decorative `<div class="rr-reports-tape no-print" aria-hidden="true">` after the header.
- Sidebar: added a "Main menu" label and an inline SVG icon (`aria-hidden`) in each nav link. Link text, `href`, `data-rr-href`, `aria-current` and the Notifications pill are untouched.

- Added `rr-reports-table` to the existing table panel's classes.
- No `data-rr-*` attribute, id, form field or table row/column was removed or reordered.

## Anything the integrator must know
- Only `index.html` and `screen.css` changed. Nothing in `_shared/` was edited. I did not have the real `_shared/app.css`, so I checked the page against stand-in styles; please look at it once with the real shared files. Where Bootstrap utilities win, a few rules use `!important`.
- `.staff-main` gets `min-width: 0` so a wide table scrolls inside its panel instead of widening the whole page (otherwise a grid shell can stretch past the viewport).
- The Location column has `min-width: 300px` on desktop, so below about 1100px of content width the table scrolls horizontally inside its panel. The mobile card layout takes over under 768px.
- The mobile cards use `display: grid` on table rows, which can drop table semantics in some screen readers. The header row is kept as visually hidden text. Add `role="row"` / `role="cell"` in the React markup if this matters. The "Officer:" label on mobile is generated by CSS.
- The Flagged and Verified-only toggle pills use `:has(input:checked)`. In very old browsers they simply don't light up; the checkbox still works.
- Print: the table region is reset to a plain light document (white background, black text, no card styling) so Print / PDF stays readable. I could only test this without the shared `.no-print` rules, so please check one real print preview.
- New static copy (eyebrow, subtitle) needs no data binding. The `rr-reports-break` span is purely visual and can be dropped in React if the filter layout is rebuilt with CSS grid.

## Mobile burger menu (added later)
- Under 992px the sidebar turns into a sticky top bar (logo, and a menu button on the right). The navigation, the user name and Log out open from the button as a vertical list. At 992px and above nothing changes.
- Structural: added `<button class="rr-reports-burger" type="button" aria-expanded="false" aria-controls="site-nav" aria-label="Open menu">` as the first child of the `<aside class="sidebar">`, and `id="site-nav"` on the `<nav class="side-nav">`. Added a small inline `<script>` at the end of the body. The existing links, `data-rr-*` attributes and the "Main menu" label are unchanged.
- New classes: `rr-reports-burger`, `rr-reports-burger-bars`, and the state class `rr-reports-menu-open` (added to the `<aside>` while the menu is open).
- In React: keep an `open` state, put the `rr-reports-menu-open` class on the `<aside>` when it is true, and set `aria-expanded={open}` and `aria-label={open ? "Close menu" : "Open menu"}` on the button. Close it on Escape and when a nav link is chosen. The inline script in the mockup is only a stand-in.
- The CSS forces the page into a single column under 992px (`.staff-shell { display: block }`) and makes the sidebar `position: sticky`, so it does not depend on the shared breakpoint for the sidebar. Please check once against the real `_shared/app.css`.

## Small-screen safety (added later)
- Checked every screen at 320, 360, 390, 414, 600, 768, 820 and 991px, including with shared styles that give inputs a large `min-width`, for anything that sticks out past the screen edge.
- Fixes in `screen.css`: filter-bar controls may always shrink under 576px and sit one per row under 420px (so dates and dropdown labels are never cut off); anything that still spills sideways is clipped on `.staff-main` under 992px (tables and the chart image keep their own sideways scroll); long words in table cells and panel text may wrap; images and SVGs never exceed their container. The Export / Print buttons in the header wrap on narrow screens.
